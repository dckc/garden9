In `scripts/jobs/common.sh`, the `ensure_clone()` function (around line 541) calls `git -C "$dir" config user.name …` bare, with no disk-space guard. When the filesystem is full, git silently fails with "error: failed to write new configuration file …config.lock", and `set -e` exits the caller with whatever exit code git returns (not a meaningful EX_TEMPFAIL). The fix: add a `df`-based check immediately before the two `git config` calls (and before the `git clone`) that emits `die "insufficient disk space on … (${avail_kb}KB free); cannot write git config — free disk space and retry"` when available kilobytes fall below a configurable floor (e.g. `${GARDEN_MIN_DISK_KB:-51200}`, 50 MB). This turns the cryptic lock-write error into an actionable one-line diagnostic that names the disk and the free space. Note: freeing the disk itself is an operator task; this fix only makes the next occurrence self-describing. The failure signature is: service=garden-repo-watcher, error="failed to write new configuration file …config.lock", filesystem /dev/mapper/pve-root at 100% (55 MB of root-reserved space only).
