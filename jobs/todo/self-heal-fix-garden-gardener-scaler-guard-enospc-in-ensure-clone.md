In `scripts/jobs/common.sh`, the `ensure_clone` function calls `git config user.name` and `git config user.email` after verifying `.git` exists (lines ~549-550). When the disk is full these git calls fail with exit 4 (`failed to write new configuration file .git/config.lock`), which propagates as a fatal under `set -euo pipefail`. The fix: wrap these two `git config` calls in a guard that detects ENOSPC by capturing their exit code and stderr; if either fails with ENOSPC (match `No space left on device` or git exit code 4 on a lock-write failure), emit a WARN and `exit "$GARDEN_OFFLINE_RC"` so the scaler skips cleanly rather than crashing. This is the same skip-on-transient pattern that `sync_clone` already applies to network outages. The immediate disk-full cause (Proxmox `pve-coolv` at 0 bytes free) requires separate manual intervention; this fix stops the restart loop until space is restored.
